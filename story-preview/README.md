# Проверка истории

Отдельное веб-приложение без зависимостей. Требуется Node.js 20+.

```sh
cd story-preview
npm run dev
```

Адрес: http://127.0.0.1:5180. Другой порт: `PORT=5181 npm run dev`.
Проверки: `npm test`.

## Работа

- Слева — одно окно: герой с портретом слева, другой говорящий справа, закадровый текст без портрета. Не назначенные изображения заменяются нейтральной заглушкой. Маски не подменяются раскрытыми обликами.
- Справа — полное дерево сцен, реплик, ответов и дополнительных разговоров. Текущий узел выделен. Поиск, сворачивание и кнопка перехода к текущему узлу работают независимо от прохождения.
- Клик по узлу включает проверку выбранного места с текущими состояниями. Условия самого выбранного окна обходятся, последующие переходы учитывают состояния. Это не автоматическое восстановление пути к узлу. Панель под диалогом позволяет задать необходимые решения вручную.
- «Назад» возвращает окно вместе с состояниями до действия. Новое прохождение очищает только состояние этого приложения. Прогресс хранится в его localStorage и не касается игровых сохранений.
- Каждый бой — одно окно с победой или проверкой поражения. Числа, предметы, навыки и награды не рассчитываются. У занятий работают только разговоры; услуги не моделируются.
- Для проверки слабого/развитого голоса и малого/большого наполнения есть независимые переключатели состояний. Они не вводят балансные пороги в игру.

## Данные

Приложение исполняет `../data/story-preview.json`, читает каталоги персонажей, существ и портретов из `../data`, изображения отдаёт прямо из `../images`.

`story-preview.json` — явно разобранный граф для сюжетной проверки по авторскому `story.json`. В нём находятся все реплики, подписи сюжетных кнопок, условия, эффекты, переходы и структура дерева. JavaScript не содержит текстов истории или проверок конкретных героев, глав и решений. Исходные инструкции не исполняются и не показываются вместо текста.

Обновлять граф при изменении авторского JSON по [правилам редактирования](../data/STORY.md). Отдельной Markdown-версии сценария нет. `sources` хранит отпечатки сверенной редакции; при расхождении приложение показывает предупреждение. После изменения самого графа повышать `revision`, чтобы старое состояние проверки не ссылалось на удалённые узлы. Обновление отпечатков не заменяет содержательную сверку. Основной `story.json` остаётся авторским конфигом; Godot получает исполняемый граф через `tools/compile-story.py` вместе с игровыми настройками. Стенд сам по себе не моделирует боевой баланс и услуги.

Формат узла: `id`, `scene`, `kind`, `text`, `next`, необязательные `speaker`, `when`, `effects`. Выбор содержит ID узлов `option`; ответ ведёт к реплике героя, ответной последовательности, эффектам и общей части либо обратно в меню вопросов. Эффекты применяются после ответа, чтобы условные реплики видели состояние до изменения. Поражение фиксирует снимок условий при входе и не перескакивает ко второму раскрытию после показа первого.

Сервер доступен только на loopback. Из `data` отдаётся явный список конфигов; сессии и остальные файлы проекта не раздаются. Новые ассеты не копируются.

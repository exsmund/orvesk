# Сюжетная кампания в Godot

Мобильное приложение проходит «Последнего носителя»: пролог, шесть глав по пять боёв, обязательные сцены остановок, выбор одного занятия, финальный разговор и одна из трёх концовок. Седьмая карта не создаётся. Браузерная игра пока использует прежний режим.

## Источники и исполнение

- `data/story.json`: главы, фиксированные карты, встречи, связи и авторские требования.
- `data/story-preview.json`: проверенный граф реплик, ответов, условий, эффектов и повторов. Авторские инструкции в интерфейс не выводятся.
- `data/story-gameplay.json`: все новые числа, привязки сюжетных наград, услуги и условия молчания.
- `data/journey-rules.json`: существующие правила уровней противников, стили распределения характеристик/экипировки, число случайных кузниц и чередование режимов.
- `data/portrait-presentation.json`: круглый crop `cover` 50% 25% по ART_DIRECTION; прямоугольный `contain`.
- `tools/compile-story.py`: проверка отпечатков, ссылок и эффектов; вставка границ обычных наград. `mobile/scripts/sync_content.py` пересобирает `content/generated/story-runtime.json` и доставляет каталоги/изображения. Производные JSON вручную не редактировать.

В GDScript нет списка сюжетных персонажей, видов, предметов, навыков или типов урона. Сценарий задаёт вид встречи, а экипировку выбирает общий генератор по ограничениям каталога. Люди остаются людьми; условные встречи 3.3 и 5.7 определяются после выбора, используют зафиксированный при создании главы уровень и сохраняются для повторов. Уровень, карта, маршрут и уже созданные враги не меняются от прокачки или поражения. На первой карте все пять врагов, включая босса, имеют характеристики по 1, 30 HP и не получают экипировку; introductory используется только при наличии такого варианта у заданного вида. Босс и последующие главы используют обычные фигуры.

## Уровни противников

Мобильные параметры хранятся в `data/journey-rules.json`. Первая карта — фиксированные характеристики по 1 у всех пяти противников (уровень 0). Начиная со второй карты, при уровне героя L на момент создания карты: `max(1, L−2)`, `max(1, L−2)`, `max(1, L−1)`, `max(1, L−1)`, `L` (для допустимых героев L ≥ 1). Прокачка внутри карты и повтор после поражения не меняют стартовый L. У демона первой карты обычные природные фигуры; вводный профиль боссу не назначается.

`enemyBalanceVersion=2` обновляет сохранённые профили врагов по прежним индивидуальным seed и стартовому уровню карты. Виды, имена, портреты, выбранные сюжетные варианты, маршрут, герой и текущий RNG сохраняются. Условные встречи, ещё не созданные до выбора, сразу генерируются по новым правилам. Уже выданная колода, текущий бой, раскрытие и итог боя не меняются; обновлённый профиль применяется к следующему бою или повтору карты. Награды за завершённые бои не пересчитываются. Сохранения версии 6 не удаляются.

## Начальный баланс

Это настройки прототипа, а не утверждение о финальной сложности кампании. Канонические значения находятся в JSON; при изменении чисел обновить этот раздел и контрольный прогон.

| Событие | Настройка |
|---|---|
| Развитие голоса | Начальное учитываемое наполнение 0; после первой потраченной на характеристику единицы — обрывочный голос, от 20 — связный, от 60 — высокое наполнение |
| Пополнение | Только фактически списанная стоимость успешно сохранённого повышения; получение награды и покупка на рынке не пополняют аттрактор |
| Костёр и лечебница | Полностью восстанавливают здоровье и выносливость; лечебница затем продолжает свой диалог |
| Кузница | Одно бесплатное переоснащение из трёх предложений; появляется на 0–2 остановках главы, как раньше |
| Рынок | Одна покупка из трёх предложений; цена `1 + 2 × уровень предмета + tier`, без склада/инвентаря |
| Подбор предметов услуг | Можно надеть сразу; уровень ограничен характеристиками, tier — суммой характеристик минус 3; уже надетая копия исключается |
| Продажа лекарств | Одна текущая цена повышения характеристики |
| Осколки мародёра | Половина текущей цены повышения, округление вверх |
| Продажа семян | Полторы текущие цены повышения, округление вверх |
| Благодарность города | Один предмет на выбор из двух подходящих; при исчерпанном каталоге — продолжение без предмета |
| Прочие занятия | Только указанный в сценарии разговор и его последствия, без скрытых прибавок |

Обычные боевые награды и формулы боя сохранены. Сюжетная награда выдаётся один раз за кампанию. Передача аттрактора в концовке долга закрывает дальнейшую прокачку.

В мобильном экране награды можно отказаться от предложенных вещей и навыков; уже начисленные осколки остаются у героя. После выбора, отказа или продолжения с пустым набором проверяется текущая доступность повышения характеристики через общую котировку прокачки. Если осколков хватает и прокачка разрешена, показывается отдельный шаг «Поднять уровень» / «Продолжить». Первая кнопка открывает вкладку характеристик существующего окна героя, вторая продолжает сценарий без траты. При нехватке осколков шаг пропускается. Флаг `victoryReward.progressionPending` сохраняет этот шаг в фазе `victory`; награды уже убраны, повторного начисления и выбора нет. После прокачки окно можно закрыть и продолжить; ошибка сохранения откатывает получение/отказ вместе с переходом.

Пока камень молчит, реплики камня и обрывочное ощущение его голоса пропускаются. Признания «он говорил» в 4.4, 5.6, 6.2 и позднее признание Асте в 6.6 недоступны до появления голоса. Общие сведения и все три окончательных решения остаются доступны. Привязки этих условий перечислены в `dialogueOverrides`, не в коде клиента.

## Состояние и сохранения

Формат мобильной игры — 6 (обёртка сохранения остаётся 1). По решению владельца прототипа прежние герои не мигрируют: при запуске удаляются только распознанные payload старых версий и их такие же резервные/временные файлы. Неизвестные/повреждённые файлы и будущие версии не удаляются. Браузерные `data/sessions` не затрагиваются.

`Game.story` хранит текущий узел и сцену, снимок входных условий, решения, выполненные эффекты, выданные награды, раскрытия после смерти, наполнение, замороженные варианты встреч и число повторов. Действие, эффект, RNG и сохранение проходят одной транзакцией: при ошибке записи интерфейс остаётся в прежнем состоянии. Окно ответа героя может предшествовать эффекту решения, но выбранный вариант уже зафиксирован и сохраняется.

При поражении новая потеря, включая ноль, заменяет прежний тайник. Осколки возвращаются один раз после победы над соответствующим врагом. После окна перерождения начинается та же глава с сохранёнными решениями и сокращёнными повторными сценами. Ничья повторяет только бой, без смерти и потери осколков. Враги не «умирают заново» в обязательных диалогах повторного пути.

## Проверка

`npm run check:story`, `npm run test:story`, `npm run check:map-points`, `npm run check:story-runtime`, `npm run test:story-runtime`, `npm --prefix story-preview test`.

Godot: `tests/journey_levels.gd` проверяет все шесть глав при уровнях героя 1, 2, 3, 5, 10, 30, оба варианта условных встреч, обновление сохранённого состава, сохранность текущего боя и безопасный повтор. `tests/campaign.gd` проходит 12 маршрутов / 360 переходов через бой, все концовки, оба варианта условных встреч, три состояния голоса, услуги, поражения, одноразовые награды, сохранения и очистку старого формата. Бои в этом прогоне завершаются контрольным событием победы: он проверяет сценарий, а не сложность боя. `tests/story_ui.gd` проверяет диалоги и выборы на пяти пропорциях экрана, сохранение и откат ошибки записи. Полный список остальных проверок — в `mobile/README.md`.

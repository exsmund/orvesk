# Конфигурация фигур

Пути в обычном тексте и в обратных кавычках указаны от корня проекта; относительные Markdown-ссылки — от расположения документа.

Фигура хранится у владельца: `figures` в weapons/shields/armor/footwear/jewelry/basic-equipment/creatures, `figure` у активного навыка в skills. `data/base-actions.json` содержит человеческие кулак, блок руками и пинок. Отдельного реестра игровых названий или списка оружия в движке нет.

```json
{
  "id": "strike",
  "name": "Удар",
  "description": "Урон указан за клетку.",
  "category": "attack",
  "copies": 3,
  "shape": [
    [0, 0],
    [1, 0]
  ],
  "staminaCost": 2,
  "blockCost": 0,
  "staminaDamagePerCell": 0,
  "healthDamage": {
    "base": 3,
    "stats": ["strength"],
    "types": { "slash": 1 }
  }
}
```

- `category`: `attack`, `defense`, `support`; по ней работают множители колоды. `copies`: положительное целое число экземпляров.
- `shape`: уникальные координаты клеток. Количество клеток — `shape.length`; дублировать его отдельным полем не нужно.
- `healthDamage.base`: целый базовый урон **одной клетки**; `stats`: характеристики роста; `types`: положительные относительные доли типов из `damage-types.json`. Смешанная атака делит общий бюджет, а не получает его заново на каждый тип.
- `staminaDamagePerCell`: постоянный урон выносливости за клетку. Альтернатива — `staminaDamage: { "base": 2, "stats": ["intelligence"], "perStatPoint": 1 }`; расчёт — в [FORMULAS.md](../docs/FORMULAS.md#урон-выносливости). При наличии формулы она имеет приоритет над постоянным полем. Урон здоровью независим; пустые `healthDamage.types` позволяют атаковать только выносливость. Блок, уклонение, столкновение и сжатие действуют на оба вида урона.
- `staminaCost`: цена всей фигуры до столкновения; `blockCost`: дополнительная цена каждой клетки, реально блокирующей атаку. При слепой подготовке резервируются все клетки блока.
- `blocks: true`: блокирует входящий урон здоровью и выносливости на перекрытых клетках; цена задаётся отдельно через `blockCost`. Категория `defense` сама по себе не включает блок.
- `evades`: отменяет входящий урон на перекрытых клетках. `counter`: собственный урон срабатывает только при встрече с атакой. `healing`: лечение после урона, если владелец выжил.
- `ignoreBlocked`: разрешение занимать скалу. `art`: иллюстрация фигуры, путь относительно `images`, например `/basic-equipment/bare-hands.png`. Квадратный PNG с настоящим прозрачным фоном. У базовых действий и пинков задана явно; без неё используется `art` навыка из `skills.json` или картинка предмета-источника из `item-art.json`. Блок руками имеет отдельную иллюстрацию, не картинку кулака.
- `availability`: `emptyWeapon`, `emptyShield`, `emptyFeet` у базовых действий: доступны при пустом слоте или базовом предмете (`unarmed: true`). Обычный предмет заменяет их; двуручное оружие также запрещает блок руками.
- Базовые предметы кулак, нога и блок руками имеют `unarmed: true` и `baseFigureAvailability` с одним из условий выше. Каталог подставляет их `figures` из `base-actions.json`; в записи предмета хранится пустой массив, а числовые параметры определяются только у базового действия. Такие предметы исключены из всех случайных предложений и не масштабируются по уровню. Сборщик не дублирует их фигуры и сохраняет идентификаторы `base:*` для совместимости уже выданных колод.
- `naturalLevel`: природная атака получает уровень из минимальной характеристики профиля, как встроенное оружие существа.
- `sourceLevel`, `templateId` и уникальный `id` экземпляра добавляет код сборки; в JSON их записывать не надо.

Тип фигуры задаётся через `category`, а поведение — её явными эффектами. Обычный и сильный удар различаются формой, уроном и ценой в конфиге. Варианты оружия, эффекты и рисунки нельзя выбирать по его имени или ID. Украшения с `charmEffect` работают отдельно от четырёх карт и расходуются раз за бой.

Пассивный навык не содержит `figure`. Он может задавать `deckMultiplier`, например `{ "category": "attack", "factor": 2 }`, и/или `passive`:

```json
{ "statBonuses": { "vitality": 2 }, "maxStaminaBonus": 2, "turnOrder": "first" }
```

Поля необязательны, пропущенные числовые бонусы равны нулю. `turnOrder`: `first` или `second`, действует на каждом ходу боя. При отсутствии предпочтений либо одинаковых предпочтениях сторон первый ход определяется случайно, следующие чередуются. Уже сохранённый ход не пересчитывается. `exclusiveGroup` — строка на уровне навыка: изучение заменяет имеющийся навык этой группы в его ячейке. Бонусы суммируются, вычисляются из текущих навыков, не записываются в базовые характеристики и не повышают уровень/цену прокачки. Изучение не восстанавливает ресурсы; потеря бонуса ограничивает их новым максимумом. Пустой `figure` не создавать. Для нового эффекта расширять типизированный интерпретатор, а не добавлять проверку ID. Подробнее — [SKILLS.md](../docs/SKILLS.md).

При добавлении контента проверьте уникальность ID внутри владельца, геометрию в 3×3, целые значения урона, положительные копии, доступность иллюстрации и соответствие `healthDamage.stats` требованиям оружия. Расчёты — [FORMULAS.md](../docs/FORMULAS.md), сборка колоды и применение — [RULES.md](../docs/RULES.md).

Оружие может указывать `family` (родственные виды с допустимым совпадением форм) и `lore: { source, section }` (источник описания). Это метаданные каталога; движок не выбирает по ним эффекты. Действующие численные параметры оружия — [FORMULAS.md](../docs/FORMULAS.md#баланс-каталога-оружия).

`weightClass` у оружия — `light`, `medium` или `heavy`, независимо от `hands`. Названия и диапазоны числа клеток/цены для авторинга находятся в `weapon-weights.json`. Кулак и щиты не имеют весовой группы. Вес используется для подписи и фильтра каталога; форму и эффекты движок по нему не выбирает. Их необходимо задать явно у каждой фигуры. Проверки каталога контролируют диапазоны веса, размещение и одинаковый рост урона клетки.

# Герои Орвеска · подготовка и реакция

Локальная браузерная игра на TypeScript: React + Vite, Express, JSON-файлы. Рабочая копия: `/Users/exsmund/Projects/duelyant-v2`. Исходная версия находится отдельно в `/Users/exsmund/Projects/duelyant`.

## Запуск

Node.js 22.13+. В рабочей директории:

```sh
npm install
npm run dev
```

Открыть http://127.0.0.1:5173. Сервер по умолчанию слушает все интерфейсы (`0.0.0.0`); другой порт задаётся через `PORT=5174 npm run dev`. Для доступа только с этого Mac используйте `HOST=127.0.0.1 npm run dev`.

[Пошаговый запуск на другом Mac и телефоне в одной Wi-Fi сети](docs/RUN_ON_MAC.md).

```sh
npm run lint
npm test
npm run build
npm start
```

`npm test` включает 200 завершённых боёв новой версии и регрессионные проверки прежних движков. `npm run build` проверяет TypeScript и собирает интерфейс. `npm run balance` остаётся симуляцией прежней версии с очередями и не оценивает баланс нового поля.

## Линтер

`npm run lint` проверяет исходники, сервер, тесты, скрипты и Storybook; предупреждения тоже завершают проверку с ошибкой. `npm run lint:fix` применяет доступные автоматические исправления. Остальные замечания исправляются вручную.

Конфигурация в `eslint.config.js`: рекомендованные правила ESLint, TypeScript ESLint и React Hooks, а также правила React Refresh для Vite. Генерируемые истории, сборки и сохранения исключены. Неиспользуемые поля при отделении через object rest разрешены: так из публичного состояния удаляются скрытые действия противника. Линтер не заменяет проверку типов (`npm run check`) и тесты.

## Форматирование

Prettier использует стандартные настройки: отступ в 2 пробела, двойные кавычки, точки с запятой и ширина строки 80 символов. Отступ явно закреплён в `.prettierrc.json`, остальные параметры остаются стандартными. Версия форматтера зафиксирована в `package.json`.

- `npm run format` — отформатировать проект.
- `npm run format:check` — проверить форматирование без изменения файлов.

`eslint-config-prettier` отключает конфликтующие правила оформления ESLint. Генерируемые истории, сборки, сохранения игроков, lock-файл и исходные арт-материалы исключены через `.prettierignore`.

## Правила версии 4

Персонаж имеет пять характеристик: сила, ловкость, выносливость, интеллект, реакция. В создании все характеристики начинаются с 1: игрок распределяет 3 души по курсу 1 душа = +1. Выйти на карту можно только после распределения всех душ. Итоговая сумма 8 составляет уровень 1; после создания действует обычная цена прокачки. Внешность выбирается из 35 портретов; пол не задаётся, начальное снаряжение отсутствует. Можно создать несколько персонажей и переключаться между ними на главном экране; у каждого отдельный прогресс.

В начале каждого раунда обе стороны бросают **d6 + реакцию**. Меньший результат получает подготовку: размещает до **5 клеток** действий. Больший получает реакцию: видит готовый слой соперника и размещает поверх до **4 клеток**. При равенстве роль реакции переходит другой стороне относительно прошлого раунда; первое равенство решается случайно. Потеря равновесия уменьшает лимит на 1.

Общее поле — 3×3, земля с травой и 1–2 скалы. Генерация сохраняет возможность обычной атаки обоих бойцов. Фигуры можно поворачивать; свои фигуры не пересекаются, чужие можно перекрывать. За границы выходить нельзя. Не больше четырёх фигур за раунд, каждый жетон используется один раз. Поле выбора использует крупные текстурные клетки и два слоя, как поле результата. Фигуры в панели показаны компактно с сохранением формы; при наведении предпросмотр занимает реальные клетки поля. Нажатие на свою фигуру убирает её.

Если готовится ИИ, его слой заранее сохраняется на сервере и раскрывается игроку. Во время реакции на клетках виден прогноз потерь здоровья: зелёное число — игрока, медное — противника. Прогноз обновляется при наведении допустимой фигуры, повороте, размещении, удалении и сжатии амулетом. Общий расчёт с боевым движком учитывает блоки, обмен ударами, броню, сопротивления, проникновение огня и оставшееся здоровье; цифры совпадают с итогом для выбранной раскладки. До раскрытия действий противника прогноз не показывается. Если готовится игрок, ИИ строит ответ только после отправки слоя игрока. Кнопка завершает размещение; после реакции производится одновременный подсчёт без отдельного выбора очереди.

| Сочетание в клетке                           | Результат                                         |
| -------------------------------------------- | ------------------------------------------------- |
| Атака / пустота или вспомогательное действие | Полный урон этой части атаки                      |
| Атака / блок                                 | Эта часть атаки полностью закрыта                 |
| Атака / атака                                | Половина урона каждой стороны                     |
| Блок / блок                                  | Без эффекта                                       |
| Блок / пустота или вспомогательное действие  | −1 стойки противнику максимум за всю фигуру блока |

Урон действия делится между его клетками. Например, топор наносит 9 урона фигурой из трёх клеток; щит поверх двух оставляет 3 урона. Затем броня вычитается **один раз из прошедшего урона действия**, отдельно по типам, применяются сопротивления. Результат округляется до десятых и распределяется по незакрытым клеткам с сохранением общей суммы. Показанный урон ограничен оставшимся здоровьем. Обе стороны получают урон одновременно, возможна ничья при обоюдном нокауте.

Пинок при прошедшем уроне снимает 2 стойки, сильная атака и удар щитом — 1, магическая атака дополнительно — 1. Пинок с шансом, зависящим от обуви, и мороз вызывают потерю равновесия. При нулевой стойке в следующем раунде доступен только подъём. Передышка восстанавливает 2 стойки; подъём восстанавливает её полностью. Восстановление учитывается до одновременной потери стойки. Подъём защищает от любой потери стойки на весь раунд (атаки, блок на пустоте и Подсечка); урон здоровью сохраняется. Защита требует размещения фигуры «Подъём», действует одинаково для обоих бойцов и заканчивается после подсчёта. Урон стойке каждой атаки умножается на прошедшую долю фигуры: блок — 0 доли клетки, обмен атаками — 50% (75% против призрака), пустота — 100%; учитываются веса клеток, поворот и сжатие. Результат округляется до десятых. Плоская броня и сопротивления сохраняют проверку попадания: если урон здоровью полностью поглощён, урона стойке нет. «Напор» усиливает только урон здоровью. Блок на пустоте и дополнительный бонус Подсечки остаются фиксированными вне защиты подъёма. Пространственную защиту определяют фигуры; прежние дистанция, шаги, парирование и d20 не участвуют в новой версии.

## Предметы и фигуры

Клик по собственной или чужой вещи открывает карточку с фигурами, их размером и описанием. Сравнение показано двумя карточками рядом: слева текущая вещь, справа просматриваемая, с цветной разницей характеристик. Свой предмет показывается одной карточкой. На каждой фигуре в карточке и панели выбора указан суммарный урон до блока и брони. В карточке под фигурой приведена формула каждого типа урона с коэффициентами и текущими характеристиками владельца. Сильный удар умножает неокруглённые составляющие на 1,5; каждая затем округляется вверх, после чего они складываются. Формулы также доступны в подсказке фигуры в панели выбора. Предмет противника во время боя показывает урон с его характеристиками; свои предметы, награды и любые предметы после боя — с характеристиками игрока. Слева всегда показан урон игрока. Пассивная броня не даёт фигур. Недоступный по требованиям предмет можно осмотреть, но нельзя надеть.

Кинжал даёт два отдельных одноклеточных удара; топор — обычный удар на две клетки и сильный углом на три. Сильные атаки двуручного оружия занимают четыре клетки. Баклер блокирует двумя клетками, большой щит — квадратом 2×2. Кулак доступен только при свободной руке. Щит и двуручное оружие несовместимы, инвентаря нет.

**Эфемерный меч** требует интеллект 2, наносит магический урон `интеллект + 1`. Его обычный и сильный удары можно размещать на скалах. Собственные фигуры, границы и лимит клеток остаются ограничениями; кулак и пинок это свойство не получают.

Кольцо раз за поединок открывает скалу для обеих сторон. Амулет раз за поединок сжимает одну фигуру до клетки, сохраняя её общий урон. Украшения представлены фигурами в списке под полем: кольцо перетаскивается на скалу, амулет — на поле, после чего выбирается доступная многоклеточная фигура для сжатия. Заряды расходуются сразу после успешного применения; эффект сохраняется сервером и не отменяется снятием фигуры или перезагрузкой. Закрытие выбора без применения не расходует амулет. Заряды не восстанавливаются заменой украшения. Новый поединок восстанавливает заряды.

Подбор предмета выполняется после урона, если боец выжил. Фигуры нового предмета появляются в следующем раунде. Если оба выбрали один предмет, приоритет у подготовившей стороны; выброшенное снаряжение остаётся на земле.

## Противники и прогресс

Уровень персонажа равен сумме пяти характеристик минус 7 (минимум 1). Уровень героя фиксируется в начале путешествия (`journey.startLevel`); пять противников имеют уровни −2, −1, −1, 0 и +1 относительно него, минимум 1. Сумма характеристик врага — его уровень + 7; распределение случайное с минимумом 1. Прокачка во время путешествия не меняет оставшихся врагов. Снаряжение выбирается независимо по требованиям, урону, стилю и бюджету: `tier <= сумма − 5`, бюджет `min(12, 1 + сумма − 5)`, цена вещи `tier + 1`. Противник получает случайный портрет из того же набора, отличный от портрета игрока. Сохранённый противник не меняет снаряжение или портрет при перезагрузке. Старому бою без портрета назначается стабильное изображение без изменения его состояния.

За победу выбирается одна награда: души, навык или предмет. Количество душ равно уровню побеждённого противника + 1. Души начисляются только при выборе этой награды. Недоступные вещи нельзя сохранить на потом, но можно повысить недостающую характеристику прямо в окне награды. Поражение обнуляет весь запас непотраченных душ, ничья сохраняет его. Характеристики, навыки и экипировка сохраняются.

## Интерфейс и изображения

Центр экрана содержит кубики реакции, общее поле и фигуры. У обоих бойцов крупные портреты. При ширине до 1020 px или высоте до 760 px боковые панели показывают портреты, полоски здоровья и стойки; клик открывает окно со здоровьем, состояниями, характеристиками и кликабельной экипировкой. На телефоне портреты расположены над полем и сохраняют соотношение сторон 2:3; полоски здоровья и стойки находятся рядом с каждым портретом. Полоски видны во всех режимах. После подсчёта каждая клетка показывает оба действия и фактически потерянное здоровье сторон; нажатие объясняет столкновение. Общие потери показаны рядом. «Посмотреть ход» повторно открывает последний результат без исполнения действий. Хроника расположена во вкладке, правила — в компактном меню. Карточки предметов и хроника имеют собственную прокрутку; основной бой занимает экран.

Кубики анимируются при показе нового раунда, потери здоровья всплывают над бойцами. `prefers-reduced-motion` отключает перемещение. Перезагрузка не повторяет урон и не перебрасывает кубики.

## Путешествие и тактика (сентябрь 2026)

Новые правила применяются со следующего раунда: уже сохранённое поле, роли и скрытый план противника не пересоздаются. Старые персонажи начинают первое путешествие с текущего боя. Источник правил: `reaction-rules.ts`, `clash-damage.ts`, `reaction-engine.ts`, `journey.ts`.

- Мороз снижает лимит следующего раунда на одну клетку. Во время штрафа его нельзя обновить морозом; после штрафа ещё один полный раунд действует защита от замедления. Урон морозом сохраняется. Пинок остаётся отдельным источником потери равновесия.
- Сильная атака и усиленный блок щитом недоступны один раунд после использования. У баклера два отдельных одноклеточных блока и усиленный блок из двух соседних клеток; у остальных щитов обычный блок занимает две клетки, усиленный — квадрат 2×2. Восстановление привязано к типу приёма и не сбрасывается сменой оружия; доступность видна обеим сторонам.
- Топор: 60% урона в первой клетке, 40% в остальных. Копьё: 60% на наконечнике. Молот: 60% исходного урона здоровью и 3 стойки (4 сильным ударом). Посох: обычное заклинание выбирается между линией и углом из трёх клеток; оба рисунка одновременно запрещены. Кинжалы сохраняют две одноклеточные атаки. Поворот переносит ударную клетку вместе с фигурой; сжатие сохраняет весь урон.
- Одна случайная свободная клетка известна до подготовки. «Брешь» игнорирует пропорциональную прошедшему урону этой клетки долю плоской брони, но не блок и сопротивления. «Опора» восстанавливает 2 стойки за блок. «Напор» усиливает на 25% эту клетку и соседние по стороне клетки той же атаки, если фигура занимает особую клетку. Эффекты одинаковы для обеих сторон, прогноз использует тот же расчёт, что и сервер.
- Страж восстанавливает 1 стойки за блок, не встретивший атак. Дуэлянт получает два обычных выпада по одной клетке. Крушитель сосредотачивает 60% сильного удара в одной клетке и снимает ещё 1 стойки. Призрак атакует через скалы, но при обмене ударами получает 75% урона вместо 50%. Характеристики и ограничения экипировки сохраняются.
- На карте размещаются пять боевых событий; часть противников можно обойти по веткам. После победы выбирается обычная награда, затем маршрут: костёр полностью восстанавливает здоровье и стойку, кузница заменяет предмет предложенным без восстановления ресурсов, опасный путь — 50% и ведёт к врагу с дополнительной клеткой. Здоровье и стойка между боями переносятся. Босс пятого боя также получает дополнительную клетку. Победа над усиленным врагом расширяет выбор награды подходящим предметом максимального доступного тира (если есть ещё не предложенный).
- Поражение возвращает в начало текущей карты: все противники возрождаются, костры и кузницы доступны заново. После выбора награды босса автоматически открывается следующая карта с другим пресетом и режимом. Персонаж и экипировка сохраняются; новое путешествие начинается с полным здоровьем. Ничья позволяет повторить тот же этап с полным здоровьем. Предложения кузницы сохраняются на сервере; повторная загрузка не меняет их. Предметы по-прежнему нельзя хранить в инвентаре.

Проверка новых механик: `tests/adventure.test.ts`; массовая симуляция — `tests/reaction.test.ts`. Старые фиксированные сценарии проверяют совместимость уже подготовленного поля без новых особенностей.

### Смягчение путешествия

Уровни врагов определяются при старте путешествия. Начинающий герой встречает уровни 1, 1, 1, 1 и 2. Архетипы и навыки по-прежнему зависят от этапа; снаряжение подбирается под характеристики противника. Первый враг первого уровня без оружия; второй такого уровня получает простое оружие.

Костёр полностью восстанавливает здоровье и стойку. Кузница не восстанавливает ресурсы; старый опасный маршрут восстанавливает 50% здоровья.

Баклер даёт два независимых одноклеточных блока — «Блок I» и «Блок II» — вместо одного двухклеточного. Каждый используется один раз за раунд и занимает одну из четырёх доступных фигур. По общему правилу блок на пустоте снимает 1 стойки за фигуру (оба блока могут снять 2). Усиленный блок занимает две соседние клетки, его можно поворачивать. После использования он недоступен один раунд. Толчок щитом сохраняется. Уже подготовленный до обновления раунд доигрывается со старой формой; со следующего раунда оба бойца получают новые блоки.

### Комбинации фигур и полный прогноз

В текущем тактическом бою соседство по стороне может связать две фигуры. Диагональ не считается; поворот и сжатие учитываются по фактически занятым клеткам. Правила одинаковы для игрока и ИИ, «Подсечка» и «Опора» срабатывают максимум один раз за раунд, контратака — один раз на каждую соседнюю фигуру атаки:

- Кинжал изгнанника и «Иней» — **Контратака**: каждая соседняя по стороне фигура удара кинжалом (обычная или сильная) получает +1 колющего урона до перекрытий, эффектов поля и брони, если соседний блок щитом перекрыл хотя бы одну клетку атаки. Один щит усиливает все соседние атаки; несколько щитов не умножают бонус одной атаки. Блок руками не подходит.
- Топор пепельника — **Подсечка**: соседние удар топором и пинок снимают дополнительно 1 стойки, если обе фигуры нанесли урон здоровью после брони.
- Меч дозорного — **Опора**: соседние удар мечом и блок щитом восстанавливают 1 своей стойки, если меч нанёс урон здоровью, а щит перекрыл атаку. Восстановление ограничено максимумом и происходит перед входящим уроном стойке.

Срабатывание зависит от одновременного состояния слоёв, а не от порядка размещения или последовательности анимации. Условный бонус не включён в базовое число урона на карточке вещи; правило показано отдельно. Палитра содержит его в подсказке. На поле связанные фигуры отмечаются пунктиром и подсветкой.

В реакции единая функция `calculateClash` рассчитывает серверный результат и предварительные значения: потерю HP с ограничением оставшимся здоровьем, стойку до/после, фактическое восстановление, входящий урон стойке, объём перекрытых атак до брони и сработавшие комбинации. «Почему такой итог» раскрывает причины. При наведении показана разница от добавления фигуры; после размещения — вклад последней фигуры относительно поля без неё. Бонус контратаки отдельно показывается после брони, но до ограничения оставшимся HP. Случайная потеря равновесия от пинка не предсказывается.

Во время подготовки итоговые числа скрыты: доступны только геометрические связи и условия их срабатывания. Старые записи хроники без нового summary продолжают отображаться; новые сохраняют итог стойки и комбинации. Проверки: `tests/figure-combos.test.ts`, `tests/clash-preview.test.ts`; ручной стенд `/tests/combos-preview.html` не обращается к сохранениям персонажей.

При подготовке на клетках атак вместо названий показан урон этой клетки до защиты врага с учётом эффектов поля; сумма клеток составляет урон фигуры. Условный бонус контратаки показан отдельно («+… при блоке»). Блоки не имеют числовой подписи атаки. В реакции сохранены точные потери здоровья обеих сторон после перекрытий и брони.

В карточках предметов раздел «Комбинации» показывает правила для обоих участников связки: все щиты показывают «Контратаку» с кинжалами (включая «Иней») и «Опору» с мечом дозорного. Указаны условия, величина бонуса, ограничение срабатываний и требование соседства по стороне. Раздел доступен в сравнении, наградах, собственных и вражеских предметах.

В карточках предметов у щитов скрыты устаревшие числовые защита и сопротивления: в текущем бою блок обнуляет урон перекрытых клеток, пассивную защиту дают тело и ноги. Указаны размеры обычных блоков и их расход лимита четырёх фигур: два отдельных блока баклера занимают две фигуры, двухклеточный блок щита стража — одну. Старые поля каталога сохранены для прежнего движка; механика боя не изменена.

Щит сумеречного стража восстанавливает 1 стойки за каждую полностью перекрытую фигуру атаки противника (обычная/сильная атака, пинок, удар щитом). Все клетки атаки должны быть закрыты обычным и/или усиленным блоком именно этого щита. Частичное перекрытие, броня, встречная атака, блок противника и пустота бонуса не дают. Считаются фигуры атак, не клетки и не количество своих блоков; суммарного ограничения срабатываний за раунд нет. Восстановление складывается с другими источниками, ограничено максимальной стойкой и применяется перед входящим уроном стойке. Правило симметрично для игрока и ИИ, прогноз и хроника используют единый расчёт.

## Навыки

Персонаж может знать до трёх навыков независимо от снаряжения. За победу среди альтернативных наград предлагается один случайный ещё не изученный навык. Выбирается только одна награда. Если три места заняты, нужно явно выбрать заменяемый навык; старый теряется. В окне подробностей можно отменить выбор и вернуться к остальным наградам. Существующие награды и сохранения не перегенерируются, отсутствие `skills` означает пустой список. Навыки сохраняются при поражении, перезагрузке и новом путешествии.

Первый набор: **Уворот** — квадрат 2×2; **Шаг в сторону** — две клетки по диагонали; **Собраться** — две клетки в линию, +3 стойки до входящего урона; **Перевязка** — три клетки углом, +2 здоровья после урона, только выжившему. Восстановление ограничено максимумом ресурса. Первые два навыка отменяют весь урон здоровью и стойке в перекрытых клетках, включая давление блока. Уклонение не считается блоком щита, не давит на пустоту и не активирует его комбинации или восстановление стойки.

Фигуры навыков подчиняются общим границам, скалам, лимиту клеток текущего режима; можно поворачивать и сжимать амулетом. При подъёме недоступны. В режимах с повторными действиями каждый навык после применения восстанавливается один полный раунд независимо от остальных; в одноразовом — расходуется до следующего боя. Навыки противника видны в его карточке и описании боя, выбранные действия скрыты по обычным правилам подготовки и реакции. Противники получают 0/0/1/2/3 случайных неповторяющихся навыка на этапах 1–5 независимо от героя. ИИ оценивает защитные клетки и восстановление своих ресурсов.

Расчёт навыков общий для прогноза и сервера. В итогах показаны уклонения, восстановление и урон; лечение не уменьшает подписанный урон клеток, а выводится отдельно. Проверки: `tests/skills.test.ts`; отдельный интерфейс без доступа к сохранениям: `/tests/skills-preview.html`.

## Режимы путешествия

При создании персонажа сервер случайно выбирает `limited` («Тактика»), `free` («Свободное поле») или `expendable` («Единственный шанс»). Режим хранится в `journey.battleMode`; сохраняется между боями, при перезагрузке и повторе ничьей. После награды босса выбирается другой режим; после поражения режим сохраняется. Старые сохранения продолжают текущий путь в `limited`, без изменения уже выставленных фигур.

- `limited`: бюджет подготовки 5, реакции 4, с существующими штрафами равновесия и бонусом элиты. Фигуры возвращаются с учётом восстановления.
- `free`: только геометрические ограничения поля 3×3, собственные пересечения и скалы. Фигуры возвращаются с учётом восстановления.
- `expendable`: те же ограничения геометрии; каждая фигура предмета, базового действия или навыка расходуется один раз за бой. Отмена размещения её не расходует. Расход учитывается отдельно для каждого бойца и сбрасывается перед следующим противником. Можно пропускать ход, но при падении необходимо подняться. Подъём не расходуется. Когда у обеих сторон закончились атаки и подбор доступного предмета не может дать новые, бой завершается ничьей; повтор восстанавливает здоровье и фигуры, сохраняя этап и режим.

Общий старый лимит в четыре фигуры убран из текущего боя. Одну фигуру нельзя продублировать в одном раунде; альтернативные рисунки заклинания по-прежнему взаимоисключающие. В режимах без бюджета клеток мороз наносит обычный урон, но не уменьшает бюджет; равновесие и бонус клеток элиты не применяются. Элитная награда сохраняется.

`Fighter.spentFigures` хранит ключ источника и ID фигуры: смена оружия не обновляет ранее использованные приёмы старого предмета. Новое оружие даёт собственные неиспользованные фигуры. Сервер проверяет расход и геометрию и для игрока, и для ИИ. Фигуры расходуются только при разрешении всего раунда, а не во время чернового размещения.

## Карта путешествия

`data/journey-maps.json` задаёт фоны пресетов. Игровой генератор создаёт координаты и связи событий. `src/game/journey/journey-map.ts` выбирает конфигурацию сохранённого путешествия и рассчитывает доступные переходы. Переходы выбираются кликом на подсвеченном узле после получения награды. Карта доступна для просмотра из меню и во время боя.

`journey.path` хранит посещённые узлы текущего путешествия. Сервер проверяет исходный узел, фазу, полученную награду и ребро графа. Костёр немедленно восстанавливает здоровье и стойку, кузница не восстанавливает ресурсы и ждёт отдельного выбора предмета или отказа от замены (`forgeResolved`). Лечение и замена не повторяются после перезагрузки. Посещение остановки не запускает бой и не обновляет режим. Клик следующего противника запускает бой без дополнительного лечения; прямой путь также не лечит. Инвентарь не добавляется.

При ничьей повторяется текущий бой, маршрут и режим сохраняются. Новое путешествие сбрасывает маршрут к первому противнику и выбирает новый режим. Старые сохранения начинают отображение маршрута с текущего противника; прежние победы отмечены, неизвестные развилки не выдумываются. Старый «Опасный путь» больше не предлагается в интерфейсе; уже начатый усиленный бой сохраняет правила и награду.

Основная серверная команда карты — `travel`, разбираемая `chooseJourneyStep`. Старый HTTP `next` оставлен только для повтора ничьей/перезапуска путешествия, чтобы нельзя было обойти граф старой командой маршрута.

### Души, уровень и награды

Вся экономика — в `src/game/progression/souls.ts`. `Game.souls` — целое неотрицательное число, новый герой начинает с 0. Уровень вычисляется по характеристикам, не хранится отдельно. Цена повышения любой характеристики на +1: **текущий уровень + 2 души**. После покупки уровень растёт, следующая покупка дороже. На сервере проверяются фаза, выбранная характеристика, ожидаемые уровень и баланс; повторное или устаревшее действие не списывает души.

Души — альтернатива навыку или вещи в наградах. Выбор имеет фиксированное количество, рассчитанное по уровню побеждённого врага; прокачка при просмотре не меняет награду. При поражении запас обнуляется в момент завершения боя, а потеря записывается в хронику. Потерянные души остаются у победившего противника и возвращаются сразу после победы над ним, дополнительно к выбранной награде. Новое поражение заменяет предыдущий запас, даже при потере нуля душ. Ничья запас не меняет. В новом путешествии уровни карты пересчитываются от нового уровня героя.

Баланс душ виден сверху карты, в списке персонажей и в карточке героя. В карточке один блок характеристик; вне боя в нём доступны кнопки +1 и текущая цена. Во время боя прокачка запрещена. В требованиях предмета-награды можно докупить характеристику за души; повышение сохраняется сразу, даже при отмене выбора предмета.

На карте открывается обязательное окно наград: квадратные изображения в один ряд без подписей. Клик открывает подробности с «Отмена» и подтверждением. Души показывают баланс до/после, навык требует выбора одной из трёх ячеек, предмет сравнивается с текущей экипировкой. Главное окно нельзя закрыть до принятия награды. На телефоне оно полноэкранное, прокручивается центральная часть, кнопки закреплены.

Ячейки навыков сохраняются точно: пустые места обозначены `null`. Сервер проверяет содержимое заменяемой ячейки и удаляет перезарядку прежнего навыка. Иллюстрации: `public/skills/*-v1.png`; душа: `public/ui/soul-wisp-v1.png` с прозрачностью по контуру.

Проверки экономики: `tests/souls.test.ts`, ячеек навыков: `tests/skill-slots.test.ts`, лечения: `tests/healing.test.ts`. Интерфейс без API и сохранений: `/tests/reward-map-preview.html`.

## Главное меню

При открытии игры показывается стартовый пейзаж. «Продолжить» доступно при наличии загружаемого сохранения и открывает последнего сыгранного героя (порядок хранится в реестре браузера). «Новая игра» открывает создание персонажа. «Герои» открывает список; выбор показывает карточку с экипировкой, навыками, душами и доступной вне боя прокачкой. Просмотр карточки не меняет последнего сыгранного героя; кнопка «Продолжить приключение» открывает выбранную игру.

`tests/start-screen-preview.html` — изолированная проверка меню, двух героев, прокачки и возобновления. Не обращается к API сохранений и не пишет в хранилище браузера.

Создание открывается поверх пейзажа главного меню в модальном окне: один портрет со стрелками и имя → распределение характеристик. Крестик возвращает в меню; черновик не сохраняется. На втором шаге можно возвращать очки кнопками «−» и возвращаться к портрету, сохраняя черновик. Сервер проверяет пять целых характеристик не ниже 1 с суммой ровно 8.

## Структура исходников

- `src/main.tsx` — точка входа React; `src/app/App.tsx` — состояние приложения и переключение экранов.
- `src/app/styles/` — глобальные стили и общие текстуры интерфейса.
- `src/game/` — правила и типы, общие для клиента и сервера, без React и CSS:
  - `combat/` — расчёт боя, фигуры, комбинации, поле и ИИ;
  - `progression/` — души и стартовые характеристики;
  - `journey/` — маршрут и события путешествия;
  - `equipment/`, `skills/`, `characters/` — каталоги и предметные правила.
- `src/features/` — интерфейс по областям: `home`, `characters`, `combat`, `journey`, `rewards`, `equipment`, `skills`. Компоненты, их стили и клиентские хуки лежат рядом.
- `src/shared/ui/` — общие модалки, `ModalFooter`, готические контролы и рамки. Не зависит от игровых экранов.
- `server/` — HTTP API и файловое хранение сессий.
- `data/` — JSON-каталоги и сохранения; `public/` — игровые изображения и текстуры; `assets/` — материалы генерации.
- `tests/` — тесты правил и изолированные браузерные превью; их URL сохранены.
- `scripts/` — вспомогательные инструменты, включая оценку баланса.

Новый UI-код размещайте в соответствующей области `features`, переиспользуемые контролы — в `shared/ui`, авторитетные игровые правила — в `game`. Стили импортируются рядом с компонентами; порядок глобальных CSS-импортов в `App.tsx` важен для каскада. Не импортируйте UI или браузерное хранилище из `game`: эти модули исполняются и на сервере.

После создания герой открывает карту путешествия. Первый бой начинается только после выбора и подтверждения первого противника; выход и повторное открытие героя сохраняют ожидание на карте.

### Пресеты карт путешествия

Художественные требования к изображениям карт и фонам боя — [MAP_ART_DIRECTION.md](MAP_ART_DIRECTION.md).

`data/journey-maps.json` — конфигурации лесной тропы, степи и руин. Новый пресет добавляется записью в этот массив: уникальный `id`, `name`, `background` (путь относительно `public`), `battleBackground` (фон боя 1672×941, отображается с сохранением пропорций через cover), размеры холста `width`/`height`. Координат, связей и событий в пресете нет. Изображение — 3000×2400, без троп, площадок и активной области. Координаты узлов — проценты независимой схемы 9:16: ширина 450 CSS px на md/lg и 80% экрана на sm. Фон через cover покрывает всю прокручиваемую область (не меньше экрана), без затемнения краёв. Значки соединены прямым пунктиром без обхода пустых точек; значки и пунктир прокручиваются вместе с фоном. Горизонтальной прокрутки нет.

**Генератор пресета карты** создаёт изображения и их конфигурацию по `MAP_ART_DIRECTION.md`. Пресет отвечает только за окружение.

**Создание карты в игре** выбирает пресет и режим, генерирует независимую геометрию (четыре последовательных разветвления, 13 точек, случайные асимметричные координаты), назначает события и сохраняет расстановку в `journey.map` (`nodes`, `edges`). На одном пути размещаются четыре противника и босс, по порядку уровней −2/−1/−1/0/+1 относительно зафиксированного уровня героя. Начало всегда первый противник, конец — босс. Боковые ветки позволяют обходить противников, но не предлагают выбор между двумя противниками сразу. Случайно размещаются 0–2 кузницы и 1–4 костра; сочетание количеств выбирается из помещающихся в пресет. Остальные точки пропускаются, соединяя соседние события по существующим цепочкам тропинок; одинаковые переходы объединяются.

Сервер проверяет переходы по сохранённому графу событий. Победу над пропущенным противником не засчитываем. Расстановка и подготовленные противники сохраняются при загрузке, ничьей и поражении. После награды босса создаётся новая карта с другим пресетом и режимом (если альтернативы есть). Проверки графов, генерации и всех переходов — `tests/journey-map.test.ts` и `tests/journey-generation.test.ts`.

- `npm run storybook` — отдельный каталог на http://127.0.0.1:6006, игровой сервер не требуется.
- `npm run build-storybook` — автономная сборка в `storybook-static/`.
- `npm run storybook:catalog` — обновить автоматически собранные сведения.
- `npm run test:storybook` — проверить отрисовку 44 экспортируемых примеров и наличие файлов ассетов (серверный рендер; интерактивность проверяется в браузере).

Раздел **«Каталог проекта / Все компоненты и использование»** перечисляет все React-компоненты в `src`, включая внутренние и неиспользуемые, с файлами, строками и родителями. Анализатор использует TypeScript и JSX-ссылки; отдельно отмечает достижимость из `App` и обращения из тестов. Условные ветки считаются используемыми. Динамическое создание компонентов без JSX не анализируется. Корневой `App` описан в каталоге, но не запускается: он обращается к игровому API и реальным сохранениям.

Раздел **«Компоненты»** содержит живые примеры всех экспортируемых UI-компонентов, кроме `App`. Внутренние компоненты показаны в составе родительских примеров. **«Состояния интерфейса»** показывает CSS-контролы, рамку портрета, отключённые кнопки и размеры модальных окон. Демонстрации используют фикстуры и хранилище в памяти; локальные черновики боевого поля записываются только в sessionStorage отдельного origin Storybook. Действия навигации, которые выходят за пределы отдельного компонента, не запускают реальную игру.

Раздел **«Каталог проекта / Все ассеты»** включает каждый файл из `public/`, `assets/` и `refs/`, в том числе старые варианты и исходные генерации. Есть поиск, фильтр по папке, превью изображений, путь, размер и открытие оригинала. Для точных путей указаны прямые ссылки из кода, стилей и конфигов; отсутствие таких ссылок не доказывает неиспользование — часть путей собирается динамически.

Каталог и CSF-истории в `stories/generated/` генерирует `scripts/storybook-catalog.ts` перед запуском и сборкой. Не редактируйте их вручную. Добавляя экспортируемый компонент, добавьте его демонстрацию в `stories/examples.tsx`; затем перегенерируйте каталог. Настройки находятся в `.storybook/`, фикстуры — в `stories/fixtures.ts`. Статические директории Storybook перечислены явно: папка с сохранениями `data/sessions/` не публикуется.

В списке этого браузера можно хранить до 20 героев. Кнопка удаления открывает подтверждение: после него удаляются сохранение героя и запись в списке. Создание проверяет лимит повторно перед отправкой и сериализуется между вкладками через Web Locks.

«Единственный шанс»: когда обе стороны больше не могут изменить здоровье (включая лечение и подбор нового оружия), результат определяется по абсолютному оставшемуся здоровью. Больше — победа, меньше — поражение, одинаково — ничья. «Завершить действия» отказывается от оставшихся фигур; противник доигрывает автоматически. Нокаут имеет приоритет. Перед каждым новым боем показывается окно правил режима.

Выбор сохранённого героя открывает карту. Текущий боевой узел продолжает незавершённый бой без изменения состояния; после ничьей повторяет бой. Поражение сбрасывает путь к первому узлу, сохраняя пресет, режим, номер путешествия и зафиксированные уровни противников. Новая карта выбирается после завершения всего путешествия.

### Бросок реакции

Перед каждым новым ходом `InitiativeRoll` показывает два 3D-кубика на Three.js поверх игры. Сервер заранее задаёт `playerDie`, `enemyDie` и `preparer`; анимация только воспроизводит результат, без повторной генерации. После броска идут остановка, числа с бонусами реакции, объявление первого участника и закрытие оверлея. Планирование заблокировано до завершения показа. При следующем ходе показ начинается после закрытия повтора предыдущего; на карте он не запускается. При отключённой анимации в системных настройках вращение пропускается. Отказ WebGL не блокирует числовой результат и продолжение игры.

Отдельный пример: Storybook → Компоненты → Бой → Бросок реакции. Тест `tests/dice-scene.test.ts` проверяет ориентацию всех шести граней.

### Сборка приложения и состояние

- `src/app/App.tsx` выбирает стартовый экран, список героев, создание или игровой экран и подключает общие стили.
- `src/features/session/useGameSession.ts` отвечает за загрузку и создание сессии, сохранение списка героев, отправку действий, блокировку повторных запросов и обработку ошибок сервера.
- `src/shared/api/client.ts` — типизированный HTTP-клиент API.
- `src/features/combat/GameScreen.tsx` собирает карту, бой и диалоги; `useGamePresentation.ts` управляет локальным состоянием представления, броском инициативы, повтором и прогнозом ресурсов. Состояние представления сбрасывается при выходе из игры или смене героя.
- `BattleJournal`, `FighterDialog` и `Rules` содержат самостоятельные панели. `LegacyArena` и `LegacyFigure` сохраняют отображение старого режима боя.

Правила боя остаются в `src/game`, авторитетное состояние — на сервере.

### Адаптивные режимы

Минимальная ширина контента — 320 px. Общие режимы: sm до 599 px, md 600–899 px, lg от 900 px. В sm модалки полноэкранные, бой использует мобильную шапку. В md/lg карточки бойцов находятся по сторонам поля. Главный экран и карта сохраняют компоновку, размеры меняются плавно. При высоте до 599 px модалки прокручиваются вместе со страницей. Общие правила — `src/app/styles/responsive.css`; новые медиазапросы должны использовать только эти границы. Container query карточек экипировки использует порог 599 px по ширине карточки.

### Постоянный состав карты

При создании карты выбираются случайные пресет и режим, затем заранее генерируются и сохраняются все пять противников (`Journey.enemies`). Уровни считаются от уровня героя в момент создания карты; прокачка и повторные бои не меняют противников. После поражения герой теряет только души; здоровье и стойка полностью восстанавливаются, характеристики, навыки и вещи сохраняются. Повторный бой после ничьей также начинается с полными здоровьем и стойкой обеих сторон. Возрождённые противники снова дают обычную награду. `Journey.lostSouls` хранит единственный запас у конкретного узла, отображаемый на карте. Старые сохранения получают состав карты при загрузке, сохраняя текущего противника.

Завершение боя остаётся на поле с результатом последнего хода. Кнопка внизу — «К награде» при победе и «На карту» при поражении или ничьей. Автоматического окна результата нет; награда открывается только по кнопке.

Игровой генератор использует 13 нейтральных точек и 16 связей: четыре разветвления подряд. Фоны не содержат маршрутов; значки и пунктир рисует интерфейс. Используются только актуальные пресеты и фоны v3.

Каталог экипировки доступен только в Storybook: раздел «Экипировка» содержит страницы «Оружие», «Щиты», «Одежда» и «Украшения». На каждой показаны все предметы категории: слева изображение, название и описание; справа характеристики, требования, эффекты и фигуры с формулами урона. На sm блоки располагаются друг под другом.

# Промпты изображений

Структура повторяет `images/`: одному изображению соответствует один JSON
с тем же путём и именем, только расширение `.png` заменяется на `.json`.

| Готовое изображение | Запись генерации |
|---|---|
| `images/weapons/dagger.png` | [items/dagger-transparent-v2.json](items/dagger-transparent-v2.json) |
| `images/hero-portraits/hero-36-alder.png` | [portraits/hero-36-alder.json](portraits/hero-36-alder.json) |
| `images/characters/city-trader.png` | [characters/city-trader-v1.json](characters/city-trader-v1.json) |
| `images/maps/forest/map.png` | [ui/journey/maps/forest-v3.json](ui/journey/maps/forest-v3.json) |

Каталоги: [items](items), [actions](actions), [skills](skills),
[portraits](portraits), [characters](characters), [creatures](creatures),
[terrain](terrain), [ui](ui). Не создавать отдельные папки по датам,
попыткам или сериям генераций. Суффикс версии сохраняется, если он есть
в имени самого изображения. Для производных мобильных копий запись не дублируется.

## Единый формат

Обязательные поля — `asset` и непустой массив `steps`:

```json
{
  "asset": "images/items/example.png",
  "steps": [
    {
      "tool": "image_gen",
      "prompt": "Точный отправленный запрос"
    }
  ]
}
```

`steps` перечисляет генерацию и необходимые правки в порядке выполнения.
При редактировании изображения добавлять шаг в его JSON; отдельные `plan.json`,
`results.json`, манифесты и текстовые файлы с промптами не нужны.

Сохранять дополнительные сведения, если они известны:

- `sha256` в корне — отпечаток текущего готового изображения.
- В шаге: `date` (`YYYY-MM-DD`), `transparentBackground`, `output` (исходный
  результат генератора), `sha256` этого результата.
- `references` — массив объектов с `path`, `role` и необязательным `sha256`.
  В роли указывать, был ли файл передан генератору или только просмотрен,
  задавал ли он внешность, материал или композицию.
- `instructions` — дополнительные инструкции к промпту, если они записывались
  отдельно; `notes` — массив пояснений о правке, экспорте или доступной модели.

Пути внутри репозитория — от его корня. Внешние исходники могут иметь абсолютный
путь. Исторический входной файл может быть уже заменён или удалён: это происхождение
изображения, а не зависимость приложения. Не приписывать неизвестные дату, модель,
референсы или результат промежуточному шагу. Текст отправленного запроса сохранять
дословно. Для составного ассета вместо выдуманного промпта указывать инструмент
сборки, исходные слои в `references` и способ сборки в `notes`; пример —
[ui/map-points/v1/combat.json](ui/map-points/v1/combat.json).

Здесь нет копий изображений, игровых характеристик, планов будущих запусков,
старых вариантов и отчётов о тестировании интерфейса. Не каждый ассет имеет
сохранившийся промпт: недостающие записи не реконструировать по догадке.
Отдельный исторический каталог существ пока находится в
[data/creatures/generation-prompts.json](../data/creatures/generation-prompts.json).

## Перед новой генерацией

Читать [единое художественное направление](../docs/ART_DIRECTION.md):
разделы портретов, предметов, действий, карт и значков.
Художественные эталоны находятся в `refs/`. Сохранённый запрос описывает выполненную
работу и не заменяет текущие требования. При переименовании или удалении готового
ассета одновременно переносить или удалять его JSON и обновлять ссылки в документации.

Отчёты испытаний, логи, метрики, контрольные снимки и временные сравнения сохранять вне репозитория.

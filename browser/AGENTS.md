# Браузерный пакет

Все команды и локальные пути ниже относятся к `browser/`. Общие требования — в корневом AGENTS.md.

## Импорты

`@/game/*` указывает на `../src/game/*`, остальные `@/*` — на локальный `src/*`. Палитра — `../src/app/styles/palette.css`. Общие JSON и изображения — в `../data` и `../public`; браузерные изображения — в `public`. Не дублировать общие файлы.

## Структура

- `src/app/` — сборка приложения; `../src/game/` — общие правила без UI; `src/features/` — интерфейсы по областям со стилями рядом; `src/shared/ui/` — общие контролы и модалки. Подробная карта — в README.
- Каждый React-компонент — в отдельном именованном `.tsx`-файле. Публичный компонент хранится в папке `Component/`: `Component.tsx`, `Component.css` (если нужны стили), `index.ts` только с реэкспортами. Не использовать `index.tsx` как реализацию.
- Внутренние компоненты одного владельца размещать рядом с ним отдельными файлами (`ItemInspection/ItemCard.tsx`, `ItemCard.css`); при усложнении — во вложенной папке. Один CSS-файл обслуживает один компонент. Медиазапросы и состояния хранятся в его CSS, а не в общем файле экрана.
- Общие типы и чистые функции компонента — в `model.ts`; специализированные хуки и рендереры рядом с владельцем. Базовые стили HTML и утилиты оформления находятся в `src/app/styles/`; общая палитра — в `../src/app/styles/palette.css`.
- Не добавлять новые предметные модули в корень `src`; не импортировать React, CSS и клиентское хранилище из `../src/game`.

## Цвета

- Все статичные значения цветов объявлять только CSS-переменными в `../src/app/styles/palette.css`. В CSS, JSX и SVG использовать `var(--color-…)`; существующие семантические алиасы (`--accent`, `--muted` и другие) должны ссылаться на палитру.
- В Canvas и Three.js получать цвета через `src/shared/lib/css-color.ts`. Числовые параметры геометрии, освещения и процедурного рельефа не являются цветами.
- Имя токена содержит группу назначения: `--color-text-*`, `--color-background-*`, `--color-border-*`, `--color-shadow-*`, `--color-effect-*`, `--color-base-*`. Перед добавлением цвета выбирать существующий близкий оттенок той же группы. Разную прозрачность и назначения не объединять.
- Текстовые цвета ограничены вариантами `Text`: primary, muted, accent, highlight, danger, success, inverse (тёмный текст на светлом фоне), home (светлый кремовый заголовок главного экрана). Не вводить дополнительные текстовые оттенки и не брать для текста цвета из других групп.
- Страница Storybook «Дизайн / Цветовая палитра» читает переменные из общего файла автоматически. Не заводить параллельный список оттенков.

## Storybook

- У каждого компонента, включая внутренние, есть соседний `Component.stories.tsx` с настоящим `component` в meta и контролами пропов. Функциональные пропы показываются как actions. У компонентов без пропов контролов нет.
- Название истории повторяет путь от `src`: `src/features/equipment/ItemInspection`, вложенный `src/features/equipment/ItemInspection/ItemCard`. Варианты того же компонента лежат рядом. Общие каталоги и межкомпонентные проверки остаются в `stories/`.
- Генератор каталога обновляет только JSON-индекс компонентов и ассетов; не генерирует и не перезаписывает CSF-истории. Фикстуры и интерактивные демонстрационные обёртки находятся в `stories/`.

- Стили Storybook применяются только к служебным компонентам и обёрткам, которые не используются в игре (например, `sb-*`). Игровые компоненты отображаются с их штатными стилями и публичными пропами.
- Не переопределять в историях CSS-классы, внутренние элементы, псевдоэлементы и CSS-переменные игровых компонентов, не скрывать части компонента и не менять его оформление через inline-стили. Обёртки не должны менять унаследованные шрифты, цвета и межстрочные интервалы игровых компонентов.
- Размер демонстрационной области и расположение примеров задавать служебными обёртками. Если нужен другой вид игрового компонента, менять его общий API/реализацию, чтобы тот же вариант был доступен в игре, а не подгонять компонент стилями Storybook.

## Типографика

- Видимый текст игры выводить через `Text` из `src/shared/ui/Text`; сохранять семантический тег через `as` (заголовки, абзацы, подписи, dt/dd). Кнопки с текстом используют `Text` внутри. Нативные значения input/option, placeholder, aria-label и текст Canvas не оборачивать в JSX.
- `size`, `color`, `font`, `weight`, `align` — фиксированные варианты из `Text/model.ts`, без произвольных чисел и цветов. `inherit` сохраняет оформление вложенного фрагмента или адаптивного контрола. Новые размеры и цвета добавлять в общий API, не локальными стилями текста.
- Страница «Дизайн / Text» содержит контролы и примеры вариантов.

## GothicTextButton

- Оформление GothicTextButton задаётся только её API: variant (primary/secondary), size (regular/compact), width (auto/full/action), disabled и aria-pressed. Не передавать className/style и не переопределять кнопку или её содержимое стилями родителей. Контейнеры задают расположение и промежутки. Secondary имеет светлый текст и серебристую рамку; disabled обесцвечивается и затемняется.

## Разработка и проверки

React + Vite, Express, JSON-файлы. Не заменять файловую базу внешним сервисом без запроса. Сервер авторитетен; скрытый ответ ИИ не раскрывается до подтверждения. Сессии в `../data/sessions`, не включать их в Git и статическую раздачу. Активный персонаж выбирается вкладкой из постоянного списка браузера; прогресс независим.

Команды: `npm run dev`, `npm test`, `npm run build`, `npm run test:storybook`. После изменений интерфейса проверить основную последовательность и узкий экран. Запуск сборки: `npm start`.
